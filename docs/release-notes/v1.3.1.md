## netlight v1.3.1

修正版：讓幾個說法更準確。不新增結論碼，也不新增任何網路連線。

### 下載
| 平台 | 建議下載（含中文使用說明 README.txt） | 只要執行檔（給 IT） |
|---|---|---|
| Windows（64 位元） | `netlight-windows-amd64.zip` | `netlight-windows-amd64.exe` |
| macOS（Apple 晶片） | `netlight-darwin-arm64.tar.gz` | `netlight-darwin-arm64` |
| macOS（Intel） | `netlight-darwin-amd64.tar.gz` | `netlight-darwin-amd64` |
| Ubuntu／Linux | `netlight-linux-amd64.tar.gz` | `netlight-linux-amd64` |

使用方式與先前版本相同，詳見 [README](https://github.com/RoccoLiang/netlight#怎麼執行)。

### 判斷更準確
- **依每個網站的實際選路判斷代理**：設定了代理、但網站命中代理例外而直連時（或環境變數只設定了 HTTP 代理而網站是 HTTPS），不再顯示「由代理伺服器代查」，也不再判為代理故障，避免叫你去關掉其實沒在用的代理。「對外連線」會註明「設定了代理，但測試的網站都直連」；技術細節逐站標示「經由代理」或「直連」。
- **使用自動代理設定（PAC）時**：程式不執行 PAC、網站實際是直連，因此系統 DNS 全部失敗時不再顯示「由代理伺服器代查」。
- **網站回應 401、403、429 時**：說明「連得上，但網站拒絕或限制這次請求」，例如需要登入、權限不足或被暫時限制次數，避免看到綠燈卻用不了而困惑。燈號與結論不變。
- 路由追蹤的「最後回應」改稱「最後有回應的節點」：中間的路由器常不回應 ICMP，最後有回應的那一站不一定是故障點。

### 給腳本與 IT
- `--json` 的每個網站多一個 `route` 欄位：`direct`（直連）、`proxy`（經由代理）、`pac`（使用自動代理設定，程式未執行、實際直連）；無法判斷時省略。既有欄位不變。

### 驗證下載的檔案
- 校驗碼：`shasum -a 256 -c SHA256SUMS --ignore-missing`
- 建置來源證明：`gh attestation verify <檔案> --repo RoccoLiang/netlight`

### 已知限制
- Windows 的路由追蹤尚未在實體電腦上驗證。所在網路擋掉 ICMP 時，路由追蹤會沒有任何節點回應，但不影響其他判斷。
- 執行檔沒有數位簽章，Windows 與 macOS 第一次執行會跳出安全提示。
